# Greystone

## Концепція і ідея

Greystone — це roguelike RPG у фентезі-сеттингу, натхненний **Cataclysm: Dark Days Ahead**, **Kenshi** і **Dwarf Fortress (Adventure Mode)**. Гравець опиняється у живому, жорстокому світі з королівствами, магією та драконами. Немає чітко прописаного сюжету — є відкритий світ, де ти сам вирішуєш що робити і ким стати.

**Головні принципи:**
- ⚖️ **Симетрія світу (фундаментальне правило):** гравець — частина світу, а не його центр. Все що може гравець — можуть NPC, і навпаки: навички, магія, бій, травми, голод, власність, спадщина, кар'єра. Будь-яка механіка пишеться для `Actor`, не для `Player`
- Світ живе без гравця — NPC працюють, торгують, воюють, старіють, одружуються, народжують дітей і помирають
- Виживання важливе: голод, спрага, травми, холод мають значення
- Все має вагу і об'єм — інвентар обмежений фізично
- Смерть — частина гри. Світ зберігається між персонажами; спадщина через заповіти. Зміна персонажів = зміна поколінь
- Прогресія без класів — усе качається через використання (зброя, магія, ремесла)
- ASCII-рендер у стилі класичних roguelike, але з сучасними зручностями (керування мишею, візуалізація шляху)

**Ключові рішення з GDD:**
- **Економіка двошарова (як DF):** активна зона = повна предметна симуляція (кожен предмет — реальний Item, фермер фізично сіє/жне/несе в комору, крадіжка забирає реальний хліб); віддалена зона = подієва абстракція (Legends Mode), розгортається назад у предмети коли гравець приходить
- **Час = DF Adventure Mode:** астрономічний, без штучного прискорення віку. Покоління через: worldgen з готовою історією (могили, предки), стрибки часу (сон/подорожі — демографія тикає), зміну персонажів (смерть героя = "retire", новий персонаж застає світ що жив)
- **Навички спільні для зброї і магії:** один enum `Skill`, одна структура `SkillLevel` (0–100, exp), живуть в `Actor` (симетрія). Техніки/закляття на одній панелі хоткеїв
- **Бій:** рандомні попадання (як CDDA/Kenshi, без вибору частини), шанс = 60 + Δdex×3 + навичка/3, урон = зброя × strMult × skillMult(0.5–1.3) ± 20%, броня захищає конкретну частину тіла

## Технічний стек

- **Мова:** C++17
- **Рендер:** SDL2 + SDL2_ttf, шрифт DejaVuSansMono 16px
- **Стиль:** ASCII символи на кольоровому фоні
- **Платформа:** Windows (mingw64)

**Команда збірки:**
```
C:/msys64/mingw64/bin/g++.exe -std=c++17 -O2 -o greystone.exe src/main.cpp src/core/astar.cpp src/core/map.cpp src/render/render.cpp -Isrc/core -Isrc/render -Isrc/entities -Isrc/ui -I"C:/msys64/mingw64/include/SDL2" -L"C:/msys64/mingw64/lib" -lmingw32 -lSDL2main -lSDL2 -lSDL2_ttf
```

## Архітектура

### Карта
- 200×200 тайлів, три шари: **TERRAIN** (земля) + **GROUND COVER** (покриття) + **OBJECT** (дерева, каміння)
- Кожен об'єкт має `objectHp` — міцність
- A* пошук шляху з octile heuristic і cost-based рухом

### Світ
- 100×100 секторна оверкарта (`overmap.h`) з біомами
- Детермінований генератор секторів за seed = координати
- Туман війни: відкривається при вході в сектор (3×3 навколо)
- Переходи між секторами при досягненні краю карти

### Актори (`actor.h`)
- `Actor` — базовий клас: позиція, символ, швидкість, тіло, 6 статів, голод/спрага, фракція
- `Body` — 6 частин тіла (голова, тулуб, 2 руки, 2 ноги), кровотеча, переломи, відрубування
- `Player` — 16 слотів екіпіровки, ефективні стати з предметів, інвентар у контейнерах
- `Enemy`, `Animal` — базова AI

### Інвентар (`item.h`, `inventory.h`)
- 16 слотів екіпіровки: HEAD, FACE, NECK, TORSO, OVER_TORSO, HAND_R, HAND_L, HANDS, RING_R, RING_L, BRACELET_R, BRACELET_L, WAIST, LEGS, FEET, BACK
- Предмети мають об'єм (мл) і вагу (г) — контейнер обмежений по обох параметрах
- На землі предмет показується символом категорії (`/`=зброя, `[`=броня, `%`=їжа тощо)
- Прикраси дають бонуси до STR/DEX/CON — реально застосовуються
- Валюта — фізичний предмет "Gold Coin" (`Items::goldCoin()`), використовується в торгівлі з NPC
- Стекування: `Item::count`/`maxStack` (за замовчуванням `maxStack=1` — не стекується). Стекуються валюта (Gold Coin — 100), їжа/питво (~10-20) і сировина (колоди/гілки/каміння — 20). Вільна функція `addToContainer(Item&, Item)` (item.h) — єдина точка додавання в контейнер: мерджить в існуючий стек, розбиває на кілька стеків при перевищенні ліміту, все-або-нічого (не лишає предмет "застряглим" напівдоданим)

### Взаємодія зі світом
- Правий клік на сусідній об'єкт → Chop/Mine/Harvest
- Удар = 20 + (STR-10)*2 пошкодження
- При знищенні падають ресурси: Logs, Branches, Stone, Berries

Хотбар з 9 слотів завжди на екрані під час геймплею (ховається лише коли відкритий сам хаб), поверх нижньої частини вьюпорту карти. Клавіші 1-9 і клік мишкою по квадратику викликають техніку зі слоту — авто-таргетить першого живого ворога впритул, потім першого жителя впритул (той самий вибір цілі що й "Attack" в контекстному меню). Порожній слот / незасвоєна техніка / брак стаміни — повідомлення в лог, дію не витрачено

## Заплановано

### Найближчий фокус: село до ідеалу (roadmap з village.md)

- [ ] **Worldgen сімей**: будинки → сім'ї (склад 1–4, віки, зв'язки батько/мати/діти/брати/вдівці, сліди історії — могили, спадок) → професії. Сім'я = спільний будинок + комора + запас грошей
- [ ] **Комора** — контейнер-об'єкт у будинку; їжа сім'ї фізично лежить там (двошарова економіка, активна зона)
- [ ] **Економічні цикли предметами**: фермер сіє → жне → носить у комору; передача Item NPC↔NPC (торгівля між жителями — коваль купує хліб у фермера)
- [ ] **Вік і стадії**: дитина/підліток/юнак/дорослий/літній/старий — вплив на speed/strength (навички НЕ падають — старі майстри = вчителі), смерть від старості біля maxAge раси
- [ ] **Демографія**: шлюби (в т.ч. між селами), народження, ріст дітей, учнівство (син переймає професію або йде до майстра), нові будинки — село фізично росте
- [ ] **Спадщина NPC**: майно/земля → дітям; без спадкоємців → старості на продаж (ті самі правила що для гравця)
- [ ] **Цілі NPC → квести**: 1–2 довгострокові цілі на жителя, квест = прохання допомогти з реальною ціллю (мисливець сам полює на того вовка)
- [ ] **Земля**: `owner` на ділянках, купівля/продаж у старости
- [ ] **Шлях до старости**: репутація + багатство + підтримка жителів
- [ ] Подієва симуляція віддалених сіл (Legends-шар) + розгортання назад у предмети

### Системи персонажа (roadmap з weapons.md / magic.md)

- [ ] **Оглушення булавою**: потрібна механіка "пропуск ходу" (stun/turn-skip) — не існує для жодного actor'а, включно з гравцем; ігнор 50% броні вже зроблено
- [ ] **Швидкість дії від зброї**: кинджал має бути дешевшим по часу — зараз кожна дія (рух/удар) коштує фіксовані 100 енергії, немає per-weapon variance

- [ ] **Техніки — розширення**: вчитель-ветеран у селі (зараз техніки відкриваються автоматично за рівнем навички, без окремого "вивчено від когось"), Обезголовлення/Оглушливий удар/Поштовх щитом з таблиці weapons.md, chase-to-technique (зараз тільки впритул), Backstab проти ворогів (потребує системи "чи ворог мене помітив" — є лише для сплячого жителя)
